## 2. 根因与修法（为什么这样改）

- **FR 事故**：带通峰 rel = 10445.82/260046.08/509646.49（差分 249600.3/249600.4），但旧 `collect_hits` 随后 snap 到未归一化全带 |c| 的 ±1200 argmax，pass1 被拉晚 **+706.18**；三点端点回归 → ppm −1415、valid=false → 全遍 invalid。
- **FL 伪 −62.4**：同一 snap 对三遍产生 +639..670 的偏置，单调变化 15.5/interval；带通峰只有 −0.62 ppm。
- **REF +12.84**：3 遍跨度 10.4 s，1 样本≈2 ppm；单遍反射使起点偏差，旧回归放大成 ppm。新判据与 `uncertainty_ppm` 比较，不显著就不重采样、不当漂移证据。
- **fit 语义**：spacing=median(accepted diffs)；accepted 由 |d−I|≤500 决定；ppm 需 ≥2 accepted 且 |ppm|≤max_ppm；anchor 取 accepted 端点中位数（不能用 o[0]，FR 事故中 o[0] 就是坏点）；残差门只标该遍；suspect 遍同样不进聚合。
- **18 dB 总 cut**：解释为“模态+宽带+shelf 负增益之和 ≤18 dB”（防 10×−12 dB 过度修正）；预算不足时对最后一段按剩余预算部分施加。这是实现取舍，Cursor 若按“每频点衰减”口径可再议（见 §5）。

## 5.1 复核结论（2026-11-16 19:15）

1. **18 dB** 维持「模态 + 宽带 + shelf 的负增益之和」。`optimize` 的 `cut_sum` 传给 `fit_broadband`，`push_shelf` 在增益为负时按剩余预算钳位。`total_cut_budget_is_capped` 对 `filters`（含这三类）的负增益求和，上限 18 dB。不是每个频点的合成衰减。
2. **`snr_band` 不进 Python 校验器，也不进 Web 本地规则。** 那两处只校验校准 YAML 的 type/q/freq/gain。`snr_band_db` 是测量报告字段，噪声窗偏保守，不参与排除。带限通道仍用全带 `snr_db` 的 20 dB 门。没有可对齐的第二套 SNR 公式。
3. **IR suspect** 回归使用 robust-t4 记录峰：`FR-ch01.analysis.json` 的 `ir_peak_idx` 238457/239990/238457（中遍偏 1533）标 `[false, true, false]`；`REF-ch00.analysis.json` 的 237119/239993/239993（第一遍偏 2874）标 `[true, false, false]`。
4. 板端 T4 十通道和 `camilladsp --check` 仍由 Lead 在板端窗口跑。本轮不连板。
