# MIMO 引擎性能与方案说明（报告补丁：单位/图例 + 为什么 CamillaDSP 不可行、Rust 引擎可行）

> 2026-11-15 初版；**2026-11-17 task-42（B1b）修正过期依据**：① 全部 rtf 数字来自缺 b−p 环形历史/多速率不读 manifest 的原型，只作“错误实现吞吐上限”，**不是可交付/验收证据**；② 删除“因果 FIR 频率分辨率 ≈ fs/taps / ART 需 1–5 Hz”论证，多速率动机改为“≤300 Hz 带宽 + 时域支撑/尾长 + 省 CPU”；③ 相位改为**因果任意相位**（M1），非默认最小相位；④ CamillaDSP 仅开发期 oracle/回退，P1 生产链为自研 host 单图；⑤ 12×16 全部标 ARCHIVE/PAUSED。
> 权威顺序：`DSP-HOST-DECISION.md` > `TSPI-RT-STACK-WBS.md` > `M1-FINAL-SPEC.md` / `rt-stack/spec/mimo-t6.md` > 本文。

## 1. 单位与图例（读表前先看）

| 符号/字段 | 定义 | 说明 |
| --- | --- | --- |
| N×M | N 个输入源通道 × M 个输出角色 | 引擎容量上限 12×10（120 路径，留 H16 输入侧扩展）；**P1 部署矩阵只声明输出角色域 G_eff = M_eff×M_eff（4.1.2 5×5=25 / 5.3.2 8×8=64）**，见 `docs/MIMO-ROADMAP.md` §1 |
| paths | 实际启用的路径数 / 全矩阵路径数 | 稀疏/带限矩阵只启用部分路径（如 60/120） |
| taps | 每条 FIR 路径的系数长度 = **时域支撑长度** | 512/1024/2048/4096；12k×2048 = 171 ms 尾长；线性相位群延迟 ≈ (taps/2)/fs 仅当选择线性相位时成立 |
| rtf（real-time factor） | 处理音频时长 ÷ 墙上时间（**平均吞吐**） | >1 表示平均快于实时；**不证明最坏块 deadline/0 miss**；正式性能门是 P2 WBS T46/T30；本文所有 rtf 来自缺 b−p 的原型，仅作量级（B-mimo P0-5/P0-10） |
| cpu% | 进程 CPU 时间 ÷ 墙上时间 ×100 | **多核合计**：>100% 表示多核并行；4×A72 满打满算约 400% |
| part/block | partitioned FFT 的分区/块大小（样本） | 128 样本；块延迟 ≈ part/fs（48k≈2.67ms、96k≈1.33ms） |
| 群延迟 | **仅线性相位 FIR** 的固有延迟 | 512→5.3ms、2048→21.3ms、4096→42.7ms @48k（96k 减半）；因果任意相位 FIR（现行默认）没有这种固有延迟，延迟由 D/Δ 决定 |
| 平台 | RK3576（4×A72 + 4×A53） | 板载 RT OEM 6.1.99-rt36；绑定 4×A72（CPU 4-7） |

## 2. 为什么 CamillaDSP 的 N×M 展开不可行（历史 bench，仅方向性旁证）

> **历史/旁证（B1b 修正）**：本节数字来自旧 bench，且部分统计自相矛盾（如 `BOARD-BENCH-RESULTS.md:20` 的 4435% CPU 在 4×A72 上不可能，B-mimo P1-15）；只可用于说明“每路径独立 Conv 展开的架构不适合 N×M 矩阵”，**不能作性能/可交付证据**。CamillaDSP 在 P1 只作开发期 oracle/回退，不执行任何生产矩阵。

做法：每个输入→输出路径放一个独立的 `Conv` FIR 滤波器 → 120 条并行滤波链。

| 配置（48k，CamillaDSP 4.1.3 aarch64） | 单线程 rtf | 4 线程 rtf | 结论 |
| --- | --- | --- | --- |
| 2×10×512 | 0.39 | 0.67 | 连最简单矩阵都到不了稳定实时 |
| 12×10×512 | ≈0.01 | 0.02 | 差 50–100× |
| 12×10×1024/2048 | ≈0.01/0.00 | — | 同上 |

原因（架构层）：
1. CamillaDSP 的每个 `Conv` 是独立滤波实例：每块对**每条路径**都要单独做前向 FFT、乘加和状态管理，N×M 路径 → N×M 次 FFT/块，频谱无法在路径间复用；
2. 默认单线程 pipeline（multithreaded 只按通道拆，120 路径仍串行/竞争），4 线程实测也只有 0.02 rtf；
3. 每个滤波器独立 WAV 系数、独立 FFT 计划与缓冲区，缓存/内存带宽被放大；
4. 结论：CamillaDSP 适合“每输出少量 FIR/IIR/PEQ”，不适合作为 ART 式 N×M 矩阵执行引擎。**P1 生产链为自研 RT host 单进程单图（R_pre→G_modal→P_post→scatter）；CamillaDSP 仅开发期 oracle/回退，P1 验收无 C 进程**（`DSP-HOST-DECISION.md:5,14,41,52`）。

## 3. 为什么 Rust 引擎可行（历史实测；数字仅作错误实现上限）

> **B1b 必读 caveat**：下表 rtf/CPU 来自**缺 b−p 环形历史**（`audio/tools/mimo-engine/src/main.rs:273-276,504-511`）、**多速率不读 manifest**（`:463`）、**无真实 IO** 的原型，且用 synth 系数。它们只能说明“共享输入 FFT 的架构方向可行”，**不能作正确性/可交付/验收证据**；修好 b−p 与真实 manifest 加载后必须复测。正式性能门是 P2 WBS T46/T30（最坏块 <50% deadline、0 miss、1/2/4≥3.2），不是 rtf 门槛（`DSP-HOST-CPU-BUDGET.md:12`；B-mimo P0-5/P0-10）。

架构：**每块只算 N 次输入 FFT（共享给所有输出）→ 每输出累加 N×P 次复数乘 → 每输出 1 次 IFFT**；persistent worker 绑 4×A72；稀疏路径直接跳过；part=128。

| 配置（RT OEM 6.1.99-rt36，4×A72） | rtf | cpu%（多核合计） | 余量 |
| --- | --- | --- | --- |
| 12×10×512 @48k | **14.93** | 231% | ~15× |
| 12×10×2048 @48k | **4.52** | 237% | ~4.5× |
| 12×10×4096 @48k | **3.06** | 295% | ~3× |
| 12×10×2048 @96k | **2.45** | 258% | ~2.5× |
| 12×10×4096 @96k | **1.66** | 320% | 历史平均吞吐（非 deadline/余量证据） |
| 12×10×2048 @48k，仅 60/120 路径 | **6.16** | 169% | 稀疏收益 +36% |

关键差异：
1. **频谱复用**：输入 FFT 每块只算 N 次（不是 N×M 次），复杂度从 O(N·M·P·FFT) 降为 O(N·FFT + N·M·P + M·IFFT)；
2. **persistent worker + 4×A72**：内存局部性好，无每块线程创建开销；实测比 v1 提升 8–90%；
3. **稀疏**：未声明路径不计算；实测半矩阵 4.52→6.16（**+36%**），更稀疏后不再线性（M16 96/192 与 48/192 几乎相同）；“带限自动降 taps”**尚未实现**，不得承诺（B-mimo P1-9）；
4. **延迟**：part=128 块延迟 2.67ms@48k（96k≈1.33ms）；taps 只决定时域支撑，线性相位群延迟（4096@48k≈42.7ms）仅在显式选线性相位时出现；**现行默认因果任意相位**，系统附加延迟由 D/Δ 决定（M1 15/25/40 ms 档，默认 15）。32 帧缓冲不改变 FIR 支撑，但 CPU 余量更紧；具体 worst 块需按 P2 门实测。

## 4. 结论与交付口径
- **P1 生产链 = 自研 RT host 单进程单图**：`R_pre → G_modal → P_post → scatter → MOTU`；host 唯一拥有 capture/playback 与 clock servo；CamillaDSP **仅开发期 oracle/回退**，不执行 N×M 长 FIR、不 fork、P1 验收无 C 进程（`DSP-HOST-DECISION.md:5,14,41,52`）。
- **rtf 1.66 不是交付依据**：它来自缺 b−p 历史/合成系数的原型（§3 caveat）。正式性能门为 P2 WBS T46/T30（同 kernel 1/2/4≥3.2、128 帧 worst<1.3333 ms、64 帧<0.6667 ms、0 miss、1h 0 xrun）；P1 只记录实际 xrun/deadline/queue，不用 rtf 签收。
- v2.1 per-route FIR schema 按 host 引擎能力落盘：per-route {source→output, coeff path, samplerate, taps, band_limit, sparse, gain}；**>4096 实验性、>8192 强警告（提示，不拒绝）**（`web/docs/API.md:335`；B-mimo P1-18）；CPU/延迟估算随 profile 报告，但不得当验收门。

## 6. 多速率动机：时域支撑 + 算力（不是“频率分辨率门”）

### 6.1 旧论证作废：`fs/taps` 不是频率分辨率下界

> 旧版“因果 FIR 可分辨频率间隔 ≈ fs/taps、ART 需 1–5 Hz 分辨率”的论证作废（B-mimo P1-7/P1-14）：**taps 不是频率分辨率下界**（短 IIR 也能在任意频点做窄带校正）；taps 真正决定**时域支撑/能建模多长的尾音**。`fs/taps` 只作名义频点间距/线性相位群延迟参考。

多速率的动机：① 低频 MIMO 只需 ≤300 Hz 带宽，12/16 kHz 已足够；② 12 kHz×2048 taps = **171 ms 时域支撑**，覆盖实测 T60≈0.3–0.5 s（经验跨度 ≥0.35–0.5×T60）；全速 48k 要同尾长需 8192 taps（4× 算力）、96k 需 16384；③ 低速率显著省 CPU。

| 运行速率 | taps | 名义 Δf=fs/taps（参考） | 线性相位群延迟（仅该模式） | 时域支撑 taps/fs |
| --- | --- | --- | --- | --- |
| 48 kHz | 2048 | 23.4 Hz | 21.3 ms | 42.7 ms |
| 48 kHz | 4096 | 11.7 Hz | 42.7 ms | 85.3 ms |
| 96 kHz | 2048 | 46.9 Hz | 10.7 ms | 21.3 ms |
| 96 kHz | 4096 | 23.4 Hz | 21.3 ms | 42.7 ms |
| 96 kHz | 8192 | 11.7 Hz | 42.7 ms | 85.3 ms |

要覆盖 T60≈0.5 s 的衰减尾，需要 ≥0.35–0.5×T60 ≈ **175–250 ms 支撑**；因此低速率 12k/2048（171 ms，边界）或 4096（341 ms）即可，而全速实现成本高。

### 6.2 方案：低音带抽取到 12/16 kHz 再跑 G_eff

低频校正只需 ≤300 Hz 带宽：抗混叠低通 + 抽取（48k÷4 / 96k÷8，或半带级联），在 12/16 kHz 运行 G_eff（M_eff×M_eff；4.1.2 5×5 / 5.3.2 8×8），再插值回全速与 host 直通支路相加；全带/保护仍由 host P_post 负责。

| 低速率 | taps | 名义 Δf（参考） | 线性相位群延迟（仅该模式） | 时域支撑 | 用途 |
| --- | --- | --- | --- | --- | --- |
| 16 kHz | 1024 | 15.6 Hz | 32 ms | 64 ms | 低延迟折中 |
| 16 kHz | 2048 | 7.8 Hz | 64 ms | 128 ms | 常用折中 |
| 12 kHz | 1024 | 11.7 Hz | 42.7 ms | 85.3 ms | 延迟敏感 |
| 12 kHz | **2048** | **5.9 Hz** | 85.3 ms | **171 ms** | **默认**（覆盖 T60≈0.3–0.5 s） |
| 12 kHz | 4096 | 2.9 Hz | 170.7 ms | 341 ms | 长 T60/<30 Hz 长模态 |
| 8 kHz | 2048 | 3.9 Hz | 128 ms | 256 ms | 仅低频段（一般不推荐） |

- 12 kHz 可表示 ≤6 kHz 内容，足够低音/低中音校正；16 kHz → ≤8 kHz。
- 抽取/插值 63-tap 对称核合计约 62/fs（48k≈1.29 ms、96k≈0.65 ms；`M1-FINAL-SPEC.md:41`），实际生产实现需实测；主要延迟来自低速率 FIR 的 D/Δ 与块累加。
- 相位：默认**因果任意相位**（延迟由 D/Δ 决定）；线性相位只作离线对照；最小相位为显式模式，必须重验路径间相对相位/交叉抵消（B-mimo P1-10）。

### 6.3 CPU 收益（历史实测；原型开销约 1.9×，仅量级）

引擎成本近似 ∝ 采样率，但**抽取/插值开销不可忽略**：历史数据全速 12×10×2048@96k rtf 2.45；线性外推 1/8 速率 → 19.6×，而实测 96k→12k/2048 仅 **10.39**，约 1.9× 开销（旧版“rtf≈19×、开销很小”作废，B-mimo P1-8）。且 10.39 来自缺 b−p/合成系数原型（§3 caveat），只能作量级；生产实现修 b−p+多相滤波后必须复测，**不得据此承诺可负担 4096–8192 taps**。

| 路径 | 处理位置 | taps/速率 | 目的 |
| --- | --- | --- | --- |
| 低频 MIMO（20–300 Hz） | 12/16 kHz 抽取域，自研 host 图内 G 节点 | 1024–4096 @12/16k | 跨扬声器低频/模态补偿（G_eff） |
| 全带（>300 Hz） | 自研 host P_post 全速（48/96k） | 每输出 PEQ/短 FIR/HP/保护 | 房间校正、分频、保护 |
| 混合 | 低速率输出插值回全速后与 host 直通/高带支路相加 | — | 全带 + 低频矩阵 |

### 6.4 建议与验收口径
1. **默认**：12 kHz/2048（**171 ms 时域支撑**，覆盖 T60≈0.3–0.5 s）；T60>0.5 s 或 <30 Hz 长模态用 4096（341 ms）；16k/2048 为延迟/尾长折中。延迟档按 M1 15/25/40 ms（默认 15），Δf 不是“分辨率门”。
2. 全带/高通/保护由 **host P_post** 负责（MIMO 不承担）；CamillaDSP 不在生产链。
3. `band_limit` 自动映射抽取/插值链**尚未实现**（B-mimo P1-1）：manifest v2 必须有显式 `role_to_slot`/`allowed_band_hz`/`band_limit`，引擎只校验/执行、不按角色名推断；48k 全速替代方案需 CPU/延迟论证，不能靠“校验拒绝”。
4. 验收：设计侧 `M1-FINAL-SPEC.md` §3；应用后 `rt-stack/spec/mimo-t6.md`（T6：同场复测/独立 holdout/T20 有效窗/两轮复现）。rtf/xrun 归 P2 T46/T30 与整链 KPI，**不是 MIMO 效果门**。

### 7.2 语义：每对输入→输出都是频率相关传递（不是静态 gain）

每个输出 j：

```
y_j(n) = Σ_i ( h_ji * x_i )(n)      # h_ji：该路径独立 FIR（复数频响 H_ji(f)，含幅度+相位）
```

- **每条路径独立 FIR 系数**：H_ji(f) = Σ_k h_ji[k]·e^{-j2πfk/fs}，可表达任意幅度/相位随频率变化（房间/扬声器/低音管理补偿），不是单点 gain；
- 所有输入→该输出的路径**先相加**，再进入 per-output 处理：HP/LP、limiter、max gain、延迟等（v2.1 输出级字段）；
- 每条路径系数可来自外部设计（WAV/raw），引擎只执行；系数元数据需带 samplerate/taps/band_limit/sparse。**当前部署只声明 G_eff 的 25/64 条路径**（其余对角直通/静音由 host 图保证），不是全 12×10/12×16 全矩阵。

- 12×16/16ch 的 schema/UI 约束**冻结为历史**：仅在用户重启 16ch/扩展项目时重新评审，不进入当前 schema/UI/预设。
