# 单点 MIMO 诊断协议 v1.2（mimo-single-point-diag-v1，按 GPT 二轮复审补强）

> 目的：在**不投入多点采样**的前提下，回答“单点应用后低频衰减是否真的变化、变化在哪一段”。
> 决策：多点（design≥6 + holdout≥3）**暂停**，直到单点四组诊断 + Apply 阶梯全部完成且解释清楚。
> 纪律总纲：**先证明测量可信 → 再证明 FIR 执行可信 → 最后证明声学效果可信**。

## 0. 前置 blocker

- **host 必须真正消费 plan（FIR）**：当前 x86 host 只有 `stereo_identity` / `plan-arena`（G），P_post 消费未接线；
- 未接通前只能做 G0（RAW）与设计侧 predicted，**不得**写“应用后无改善”。

## 1. 统一测量条件（缺一即作废）

| 项 | 要求 |
| --- | --- |
| 位置 | 同一麦位（UMIK 90° 朝上），移动后重测基线 |
| 声源 | 同扫频源/文件/通道组合 |
| 电平 | 同 `kMainTrim`(22) + 同 `level_db`（默认 −25 dBFS） |
| 时间参考 | 同 `CommonD0`/onset 对齐口径 |
| 采样链 | 48k、MOTU 22ch / UMIK 2ch、同 period/buffer |
| T20 拟合区间 | 预冻结（EDC −5…−25 dB，R²≥0.90），四组一致 |

### 1.1 重复测量一致性（**新增，GPT 要求**）

- 每通道 **3 repeats 必须逐次报**：T20、EDC@100ms、IR 峰位置/相关性；**不许只报平均**；
- **IR 互相关要区分时间参考误差（GPT 要求）**：同时报告 ①**未对齐**互相关；②允许 ±32 samples（±0.67 ms）搜索后的**最大对齐互相关**；③**最佳对齐时移**（samples）。对齐**只用于诊断**，绝对延迟必须独立保留并单独报；**禁止**通过任意平移 IR 来掩盖真实延迟变化。
- 一致性门（默认，可声明修改）：
  | 指标 | 门 | 失败处理 |
  | --- | --- | --- |
  | T20 逐次极差 / 中位数 | ≤ 10% 且 ≤ 0.15 s | 该带 `UNRELIABLE` |
  | EDC@100ms 逐次极差 | ≤ 1.5 dB | 该带 `UNRELIABLE` |
  | IR 逐次归一化互相关（主瓣 ±2 ms 内） | ≥ 0.98 | 该通道 `UNRELIABLE` |
- 三次结果若像“0.8 / 1.2 / 1.9 s”这种离散，**禁止给平均值当基线**；直接判该带不可用并记录原始三次值；
- **短 T20 提醒（GPT 要求）**：T20 < 0.2 s 时，10% 相对门可能严于测量系统分辨率 → 此时以**绝对极差 ≤0.05 s** 为主门、相对门作参考；**不得为了过一致性门而放宽拟合质量**（R²、动态范围、覆盖区间要求不变）；
- 每条测量必须同时输出：**三次原始 T20、极差、相对极差、拟合残差/R²、EDC 有效动态范围**。
- 报告必须列：每通道每带的三次值 + 中位数 + 是否通过一致性门。



### 1.6 非低音炮通道的扫频范围（用户裁决 2026-11-21）

- **除 SUB 外所有通道（FL/FR/SL/SR/HFL/HFR）扫频从 20 Hz 开始**，不得用 80 Hz 高通/限带把 20–80 Hz 丢掉；
- SUB 仍限带（当前实现 20–130 Hz）；
- 分析报告除 spec 的 40–200 Hz 八带外，另报 **20/25/31.5 Hz**（观察量，不改变 T6 门的频带定义）；
- 拟合/merge 不再默认 `--hp 80`：测量/拟合 band 默认 **20:16000**，播放侧 HP 仍按用户可配置目标（主箱 55 / 环绕 60）。

### 1.5 低频 T20 可证性（测量动态范围要求，**实测反馈新增**）

实测（ir-diag，2026-11-21）：40/50/63 Hz 的 EDC 动态范围仅 **20–40 dB**，60% 以上通道/带组合不可认证。**在动态范围不足时，任何“T20 变短/变长”的声明都不可证伪**。因此：

1. **判据**：只有**对照前(RAW)与处理后都**满足 `DR ≥ 35 dB` 且 `−25 dB 点高于噪声底 ≥10 dB` 的带，才允许做 T20 比较；否则该带只允许报告“初始段（EDC@100ms）”与绝对能量变化；
2. **采集参数（推荐下限，需冻结进 manifest）**：扫频 ≥15–20 s；repeat gap ≥ max(1.5×预期 T20, 1.5 s)；电平在窗口内可取 **−18 dBFS**（仍属低电平，且提高 DR）；每点每通道 ≥3 repeats，允许对 IR 做分位/中位数聚合；
3. **噪声控制**：采集前确认 UMIK 路无其它占用、`kMainTrim` 与电平冻结；apply 后 settle ≥1 s；噪声本底用**扫频后尾段/分块 RMS 中位数**，禁用固定“前静音均值”（会被流切换 pop 污染）；
4. **不可证伪声明**：若 DR 不足，报告必须写 `T20_NOT_CERTIFIABLE`，并给出“局部斜率等效值（−5…−20 dB）”仅作参考，不得当 T20 用；
5. **跨组可比性**：RAW 与处理后必须用同一 `parameter_hash`（FFT/窗/带通/Schroeder/拟合区间/噪声门）与同一采集参数，否则比较作废。
### 1.4 onset 可信度门（**实测反馈新增**，2026-11-21）

背景：Web→CLI 实跑中 job-0002/0003/0004 在 merge 的延迟质量门失败（SR/FL residual 664/794 samples、SL delay 5.4 s），原因是单点多次重复的起点被**反射/相邻时间槽**锁住。这类 capture 必须**拒收**而不是硬算：

1. 每个 slot 的 onset 由**互相关主峰 + 反射抑制窗**确定，且落在 nominal±0.25 s 内；
2. 逐 repeat 起点残差 **≤20 samples**（与 merge 延迟门一致），且**有效 repeat ≥2**；
3. 任一通道不满足 → 该通道 `ONSET_UNRELIABLE`，**该次 capture 作废并重测**（不得用其它通道替算）；
4. 报告中必须列每个 slot 的 nominal/actual onset 与 lag（沿用 diag.json 口径）。

### 1.3 分析一致性（RAW 与处理后必须同参数，**新增，GPT 要求**）

RAW 基线与 G1/G2/G3 的处理后测量，必须使用**完全相同的分析算法与参数**：

| 项 | 要求 |
| --- | --- |
| FFT 长度 / 补零 | 相同（冻结值） |
| 窗函数 | 相同 |
| 1/3 oct 带通 | 相同（阶数/类型/中心频率定义） |
| Schroeder 积分 | 相同（时机/归一化/截断规则） |
| T20 拟合区间 | 相同（−5…−25 dB，R² 门相同） |
| 噪声门限 | 相同 |
| 代码版本 | 同一 commit/同二进制；分析参数写成 manifest（含 hash） |

- 分析参数 manifest 必须在**采集前冻结**；任何一项变化 → 旧基线失效，必须重测，**不得**混用不同版本的分析结果做对比。
### 1.2 低频 SNR 严门（**新增，GPT 要求**）

对 40 / 50 / 63 Hz（以及任何 SNR < 25 dB 的带）额外检查，全部满足才算有效：
1. **衰减记录长度**：扫频结束后可用记录 ≥ max(1.5×T20, 1.0 s)，否则 EDC 尾部被截断 → `UNRELIABLE`；
2. **噪声底不进入拟合区**：EDC 在 −25 dB 之前的动态范围 ≥ 35 dB，且噪声底比 −25 dB 点低 ≥ 10 dB；
3. **一致的带通与 EDC**：同一 1/3 oct 带通滤波器（写清阶数/类型）、同一 Schroeder 反向积分、同一窗；
4. **拟合区间覆盖**：必须真实覆盖 −5…−25 dB（不足则 `UNRELIABLE`，不许外推）。

## 2. Apply 阶梯（**新增，GPT 要求**：先证明执行链可信）

**不能直接跳到 PEQ-only**；按四级递进，每级都要有可检查的输入输出：

| 级 | 内容 | 必须验证 |
| --- | --- | --- |
| S0 Identity FIR | 单位脉冲（delta）plan | 通道映射正确、延迟=声明 D、增益 0 dB、采样率 48k、数值精度（S24_3LE 往返） |
| S1 Known FIR（**四种子测试**） | 见 §2.1 表 | 幅度/延迟/极性/系数顺序/卷积边界逐项验证 |
| S2 PEQ-only | 当前 PEQ 配置 | 频响与 predicted 一致（≤1 dB）；说明 PEQ 走的是哪条代码路径 |
| S3 G (MIMO) | 真实求解 G | 同上 + G 的因果/延迟/极性/增益帽与声明一致 |

- **PEQ 与 G 若走不同执行路径，S2 成功不能证明 S3 正确**——每级独立留证；
- 每级留证内容：`Design → Export → Load → Apply → Capture → Analyze` 六环节的输入/输出（plan hash、host 日志、hwparams、capture sha256、分析 JSON）。


### 2.1 S1 的测试信号集（**新增，GPT 要求**）

| # | 测试 FIR | 验证点 | 通过判据 |
| --- | --- | --- | --- |
| S1-a | 纯单位脉冲 δ[n] | **绝对延迟**与幅度 1.0 | 延迟 = 声明 D（±0.5 sample）、幅度 0±0.1 dB |
| S1-b | 已知延迟 δ[n−k]（k 例如 37 samples） | **卷积起始位置/延迟补偿** | 实测延迟 = D+k ±0.5 sample |
| S1-c | 正负系数交替 FIR（如 [0.5, −0.5] / 多抽头交替） | **极性/符号处理** | 实测相位与解析一致（≤2° @1 kHz），无符号翻转 |
| S1-d | 多抽头 FIR（如 5–9 tap，非对称；含已知群延迟与幅度响应） | **系数顺序**、卷积实现、边界处理 | 实测幅度 ≤0.5 dB、延迟 ≤0.5 sample；边界无截断误差（首尾 block 输出与解析一致） |

- 四种都必须留 capture/分析证据，不能只做 S1-a；
- S1 只在**数字域/loopback 或已知声学路径**验证“执行链正确”，**不构成声学效果结论**。

## 3. 四组实验 + 重复与交错（**新增，GPT 要求**）

| 组 | 处理 | 目的 |
| --- | --- | --- |
| G0 | RAW（P_post 旁路/identity plan） | 原始基线 |
| G1 | PEQ-only | PEQ 实际效果 |
| G2 | MIMO-only | MIMO 控制效果 |
| G3 | MIMO+Reg | 正则化影响 |

- **每组 ≥3 次重复 Apply + 重复 Capture**；
- **顺序交错**（如 G0,G2,G1,G3,G0,G2…），避免温度/时钟/设备状态随时间漂移产生假差异；
- G2 与 G3 必须使用**同一测量条件、同一目标、同一执行器约束**，否则差异不能归因于正则化；
- 每次 Apply 记录：plan hash、host 启动时间、hwparams、`kMainTrim`、温度/负载。

## 4. 分析指标（初始段 vs 衰减段必须分开）

1. **初始段**：EDC(0–100 ms)、瀑布 0–100 ms 能量；
2. **衰减段**：EDC −5…−25 dB 斜率 → T20/RT60（R²、动态范围必报）；
3. 每带（40/50/63/80/100/125/160/200 Hz）：T20、EDC@100ms、绝对 dB 变化；
4. 频响：每带 `R_k` 与 `R_max`（mimo-objective-v1 同口径）；
5. 四象限（必须落一个）：A=FR 降但尾巴不变；B=初始能量降但斜率不变；C=尾巴变长/新长尾；D=几乎无改善。

## 5. 单点 M=1 的能力边界（**已按 GPT 纠正**）

H(f) 在 M=1 时是 1×5 行向量，列秩最多 1。**但“列秩≤1”不等于“无法评估控制能力”**：

| 单点**可以**分析 | 单点**不能**回答 |
| --- | --- |
| 各执行器在目标带的幅度/相位 | 空间可控性（多测点才能定义） |
| 执行器两两相关性（是否高度冗余） | 空间泛化/多点一致性 |
| 是否存在可有效抵消目标声压的执行器组合 | 完整列秩/全局条件数（M≥N 才有意义） |
| 所需控制增益是否超限 | 多位置折中解 |
| 正则化前后解是否稳定 | holdout 泛化 |

→ 结论：**单点能回答“时间域有无变化、单点控制是否稳定”，不能回答“MIMO 空间上是否可行”**。这是两个不同问题。

## 5.1 实验顺序（**新增**）

**先在数字域完成 S0/S1**（证明执行链正确），**再做 S2/S3 真实声学验证**。
**S0/S1 通过 ≠ 声学效果通过**：前者只证明“FIR 被执行了”，后者才回答“房间低频衰减有没有变化”。两者报告必须分开。

## 6. 结论使用规则

- A/B → 与“开环 FIR 不能移除房间极点”一致；T20 目标需另立物理方案（吸声/摆位/闭环阻尼），**但这不代表 FIR 无价值**（初始能量降低是独立收益）；
- C/D → 先查 apply 是否生效、G 的因果/延迟/极性/相位，再谈优化；
- 任何结果都不能单独用 predicted 声称 PASS；多点采样在单点结论清晰前不启动。

## 7. 单点完成门 → 随后立即进入多点（**用户裁决，2026-11-21**）

**顺序是硬的：先把单点做到“可信且完整”，然后立即进入多点采样（多点不是暂停/取消）。单点未完成前不投入多点、不做空间结论。**
