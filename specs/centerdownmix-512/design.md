# 技术方案

状态：**已定稿（2026-11-22）**。实施任务见同目录 `tasks.md`。

需求见同目录 `requirements.md`。本方案只增加一条显式的 5.1.2 单流路径。现有 7 声道 4.1.2 接收、未声明时的 8 声道行为、`CenterDownmixPlan` 的系数和折叠算法都不改。

## 1. 结论

5.1.2 的 8 个声道按线上顺序原样进入图输入缓冲。中置折叠仍由 `content_map` 在这块缓冲上完成。声道重排只放在一张新的 plan 里：形状沿用现成的 `TestPlan::multichannel_412_from_51_content`，高度两路改为取源下标 6 和 7，不再填零。

7 声道那条「先按 H16 角色收成 4.1.2，再让 plan 对角直通」的路径继续只服务已经是 4.1.2 的线序。5.1.2 不走它。

```mermaid
flowchart LR
  wire["AES67 单流 8ch<br/>L R C LFE Ls Rs Ltf Rtf"] --> buf["图输入缓冲<br/>下标与线序相同"]
  buf --> fold["content_map<br/>FL/FR += g·C，C = 0"]
  fold --> plan["新 plan<br/>in 与 out 不同"]
  plan --> spk["4.1.2 容器<br/>0 1 2 3 4 5 空 7"]
```

`g = 0.7079458`。缓冲在折叠前的下标是：0 FL、1 FR、2 C、3 LFE、4 SL、5 SR、6 TFL、7 TFR。plan 的取值是容器槽 `[0, 1, 4, 5, 6, 7, 空, 3]` 的源下标，也就是 `capture_index = [0, 1, 4, 5, 6, 7, null, 3]`。

## 2. 为什么重排放在 plan

块循环的顺序已经固定：捕获先把样本写入图输入缓冲，`ContentAdapter::apply_block` 接着改这块缓冲，然后 plan 按 `in_index` 读取。`content_map` 用输入布局的下标找 C、FL、FR。缓冲若先被收成 4.1.2，中置就不在下标 2，折叠会加错声道。

plan 允许 `in_index` 和 `out_index` 不同，也允许某个源不被任何角色选中。6 声道 5.1 的测试 plan 就是这样做的：`n_in = 6`，C 在下标 2，没有任何 path 选它。5.1.2 把同一写法扩到 8 路，高度改为有源。运行期仍然禁止一个源送给两个角色，中置扇出留在 `content_map`。

H16 角色表不适合做这次重排：

| 事实 | 后果 |
| --- | --- |
| 4.1.2 图角色表没有 C | 按角色挑选会在折叠前丢弃中置 |
| TFL/TFR 的 H16 槽是 10/11，不在 0..7 | 8 声道默认槽 `0..7` 的容器里没有高度；现有规则是缺角色就拒绝，不是静默零填 |
| 图宽等于容器宽时，`aes67_rx` 把 `capture_index` 盖成 `0..7` | 角色映射即使算出来，也会被这行恒等覆盖擦掉 |

因此这条新路径在捕获层不做 H16 角色选择。8 个线声道按顺序进入 8 个图通道。物理音箱位置只由新 plan 决定。

默认的 `(8ch flow, 8ch graph)` 仍标成 `4.1.2-8ch`，仍走现有角色表。本方案不把它修成一条可用的 4.1.2 或 5.1.2 接收。已经在跑的是 7 声道加显式槽 `[0, 1, 4, 5, 10, 11, 3]`。

## 4. plan

新 plan 与现有 4.1.2 测试 plan 共用 ABI v1、48 kHz、块长 128、8 容器、7 角色、槽 6 无 path。差异只在 path 的 `in_index`：

| 角色 | out | in |
| --- | --- | --- |
| FL | 0 | 0 |
| FR | 1 | 1 |
| SL | 2 | 4 |
| SR | 3 | 5 |
| TFL | 4 | 6 |
| TFR | 5 | 7 |
| LFE | 7 | 3 |

源下标 2 不出现。每条 path 仍是增益 1 的对角基线系数，只是输入下标不再等于输出槽。`graph_id` 使用新的种子字符串，避免和 `52f2f3ad…` 那张 identity plan 相撞。

生成器放在现有 `make_plan_412_test.py` 的新模式里，例如 `--mode from-512`。身份模式的打包顺序、CRC 和输出文件布局保持原样，避免生产用的 identity 二进制被顺手改掉。

## 5. 配置与启动闸

声明方式只有一处：`[content] input_layout = "nsp-5.1.2"`，且 `output_layout = "4.1.2"`、`center = "auto"`、`program_peak_dbfs = -18`。捕获必须是一条 8 声道 userspace AES67 flow，图输入宽度 8。缺任何一项都拒绝启动。

这组配置同时完成三件事：

1. 捕获按线序填充，报告里的 flow 名用第 3 节的新名字。
2. `content_map` 在进 plan 之前折叠中置。
3. 已解析的 plan path 必须与第 4 节的七行一致。不一致就拒绝启动。

宽度校验不够。identity plan 也是 `n_in = 8`、`n_out = 8`。若只查宽度，5.1.2 会把清零后的中置送进环绕左。启动闸用 path 表本身，不另造一套路由配置。

未写 `[content]` 时，host 不启用折叠，`(8, 8)` 的 flow 名仍是 `4.1.2-8ch`。7 声道槽表和 `plan-412-identity` 的 `capture_index = [0, 1, 2, 3, 4, 5, null, 6]` 保持原语义。

## 6. 设置页：两边都是角色，中间是派生流向

现有声道向导生成的是 channelmap remap，同名才直通，写不出「一个中置进左右两只音箱」。设置页不走那张矩阵。它编辑两份绑定，再派生一张流向图。播放仍由 `content_map` 做中置扇出，由 plan 做单源路由。折叠系数继续是代码里的 `0.7079458`，页面只显示，不提供输入框。

角色词表一份，输入和输出共用。每个名字同时有中文和英文简写：前左 FL、前右 FR、中置 C、低音 LFE、环绕左 SL、环绕右 SR、后左 BL、后右 BR、高度前左 TFL、高度前右 TFR、高度后左 TRL、高度后右 TRR。旧预设里的 `HFL`/`HFR` 读入时当成高度前左/前右，`SUB1` 当成低音 1。低音 2、低音 3 只在低音炮数量为 2 或 3 时出现。

输出页三块：

1. 音箱清单：有没有中置；低音炮数量 0、1、2 或 3。
2. 物理槽列表：每个输出槽一个下拉，选项是中文加简写，或空。套用 `4.1.2` 时填入槽 0..5 与槽 7 的现有接法，槽 6 为空。之后可以逐槽改。
3. 保存校验：清单和逐槽选择必须一致。无中置则不能留着 C，有中置则恰好一个槽是 C，且前左、前右都在。低音角色个数等于低音炮数量。同一个角色不能占两个槽。

输入页是同一套下拉，按通道顺序排。套用 `5.1.2` 时填入 `L R C LFE Ls Rs Ltf Rtf` 对应的八个角色。两个输入槽不能选同一个角色。

派生规则，也是流向图要画出来的线：

| 情况 | 策略 | 这次播放 |
| --- | --- | --- |
| 两边都有这个角色 | `direct` | 一条线，增益 1，plan 取这个输入下标 |
| 输入有中置，输出无中置，且前左、前右都在 | `center_downmix` | 中置分成两条线进入前左、前右，标 −3 dB；由 `content_map` 做，plan 不选中置 |
| 输入有别的角色，输出没有同名槽 | `reserved_downmix` | 图上留一条未连接的线，注明保留。不混进其它箱子。7.1.4 折进 5.1.2 属于这一类 |
| 输出有角色，输入没有 | `silence` | 该槽无源。策略字段同时承认 `upmix`，但引擎遇到 `upmix` 就拒绝启动 |

一份低音对一只低音炮是 `direct`。一只低音要进多只低音炮时，多出来的低音槽按「无对应输入」处理，不在这次把低音复制出去。

流向图放在同一设置页，左列输入槽，右列输出槽，线从左到右。中置下混画成一源分两支。没有连上的角色留在图上，不藏起来。这样后面接上混或其它下混时，加的是策略实现，不是另一套页面。

5.1.2 预设对 4.1.2 预设编译出来的 plan path，就是第 4 节那七行。人改了某个槽的角色之后，编译器按新的槽位重算 `out_index`，人不再手填下标。`/api/channelmap/draft` 仍拒绝用 remap 矩阵保存这一对。校准页不搬这套表单。页面改动只进仓库，不部署。
